# Кейс 1. Поиск нетипичного поведения заявок на закупку

## Задача
По синтетической выгрузке событий выполнения заявок на закупку (ELMA365-подобный журнал) самостоятельно определить обычное поведение, предложить критерии аномальности и составить список потенциальных аномалий с проверяемыми объяснениями. Нужно отличать нарушение процесса от необычного, но допустимого случая.

Сдаваемые результаты: `anomalies.csv` (`ProcessInstanceId,AnomalyType,Explanation`) и краткий отчёт из шести разделов.

## Данные
`data/students.csv`: 12 162 события, 1000 процессов (standard 635, urgent 168, contract 197), 4591 человеческое задание. Срез наблюдения по описанию: 1 июля 2026, 00:00 (UTC+03:00). Рабочий календарь: Пн–Пт 09:00–18:00.

## Подход
1. Загрузка и проверки качества (индексы, парность заданий, согласованность результатов); порядок событий строго по `EventIndex`.
2. Таблица заданий с календарной и рабочей длительностью (функция рабочего времени покрыта тестами).
3. Маршрут каждого процесса как строка кодов этапов; норма определяется по типу заявки.
4. Правила аномалий: нарушение схемы (порядок, обязательные этапы, роль) и резкие статистические хвосты (порог выбран по разрыву в данных, а не заранее).
5. Isolation Forest (seed 42) как независимая перекрёстная проверка, не как основной метод. Нейросеть сознательно не использовалась: нет меток, 1000 объектов, нужны проверяемые объяснения.
6. Объяснения генерируются кодом из данных, поэтому все числа в них вычисляемые.
7. Валидация итогового CSV (заголовки, существующие ID, дубли, экранирование).

## Результат
88 строк по 80 процессам (8 % журнала), 10 типов:

| AnomalyType | Процессов | Критерий |
|---|---|---|
| Skipped manager approval | 16 | бюджет создан без этапа руководителя |
| Execution before budget approval | 8 | исполнение раньше бюджета |
| Duplicate specialist check | 8 | две подряд проверки без возврата |
| Unplanned audit checks | 8 | пара внеплановых проверок auditor, причина не видна |
| Manager task performed by requester | 8 | роль requester на этапе руководителя |
| Excessive rework loops | 8 | 5–8 возвратов при норме 0–1 |
| Instant task chain | 8 | задания закрыты за секунды |
| Stalled specialist check | 8 | проверка ровно 60 рабочих часов |
| Slow specialist check | 8 | проверка ровно 8 рабочих часов у standard |
| Stalled open manager approval | 8 | открыто с янв.–фев., ~900–1030 рабочих часов |

8 процессов попали в два класса (пропуск руководителя и 60-часовая проверка), поэтому 88 строк.

## Известные ограничения
- В файле 25 событий в 10 процессах с отметками позже заявленного среза (1 июля 09:16–17:59). Считаем дефектом выгрузки: события оставлены, аномалией сами по себе не считаются.
- Класс *Unplanned audit checks* спорный: оправданность проверки по данным установить нельзя, строки помечены как требующие ручной проверки.
- Два исполнения standard (17,5 и 17,3 рабочих ч) не включены: плавный хвост без разрыва.

## Запуск
1. Откройте `anomaly_analysis.ipynb` в Google Colab (File → Upload notebook).
2. Runtime → Run all. Когда ноутбук запросит файл, выберите `data/students.csv`.
   Локально: положите `students.csv` рядом с ноутбуком; нужны Python 3, pandas, numpy, scikit-learn.
3. На выходе создаётся `anomalies.csv`, идентичный выданному в репозитории.
